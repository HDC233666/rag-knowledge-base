# 向量检索入门

## 什么是 embedding

embedding 是把文本映射成定长稠密向量的模型输出（例如 512 维）。
语义相近的文本，向量在空间里也接近，所以「RAG」和「检索增强生成」
即使字面不同，向量距离也很近。

## 相似度怎么算

两个向量做 L2 归一化后，点积就是余弦相似度，取值范围 -1 到 1。
工程上常把向量先归一化、再用内积检索，省掉每次除模长。

## 常用模型

- bge-small-zh-v1.5：中文、512 维、约 95MB，CPU 可跑，适合本地 demo；
- bge-m3：多语言、1024 维，效果更好但更重；
- OpenAI text-embedding-3-small：托管服务，按 token 收费。
换模型时注意：旧向量要全部重建，维度不同不能混用。

## 向量库怎么选

- 数据量 1 万以内：numpy 矩阵 + 余弦相似度足够，毫秒级；
- 十万级：FAISS（IndexFlatIP / IVF / HNSW）单机最省事；
- 百万级、要持久化/过滤/多租户：Chroma、Milvus、Qdrant、pgvector。
HNSW 是一种近似最近邻索引：用多层图跳转，查询快但召回不是 100%，可以调 ef 参数换精度。

## 什么时候用向量检索

同义词、口语化提问、跨语言场景，向量检索明显强于 BM25；
但专有名词、型号、数字、代码标识符，BM25 反而更准。所以生产上常做混合检索。

## 双塔模型怎么训练

双塔（bi-encoder）把「问题」和「文档」分别编码成向量，用对比学习训练：
一个 batch 里，正样本是真正匹配的问答对，负样本是 batch 内其他文档（in-batch negative）。
训练目标通常是 InfoNCE 损失：让正样本的余弦相似度尽量高、负样本尽量低。
bge 系列就是这种结构，微调时可以用少量业务数据（几千条）提升领域效果。

## 向量检索常见的坑

- 文档和问题的向量分布不一致：检索要加指令前缀（bge 的中文模型建议给 query 加
  「为这个句子生成表示以用于检索相关文章：」）；
- 长文本直接编码会丢细节：先切块再编码，块别超过模型最大长度；
- 换模型不重建索引：新旧向量维度不同，查询直接报错或召回全乱；
- 只看余弦相似度不设阈值：容易把弱相关片段也塞进上下文。
